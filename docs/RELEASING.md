# Releasing an LSADeploy build

A packaged build must come from a clean checkout. Do not add phone logs, local
SSH helpers, private keys, runtime sockets, PID files, or generated bytecode to
the release tree.

1. Build the package with `tools/build_deploy_package.ps1`.
2. Confirm the generated `LSADeploy` directory has the expected payload hashes
   and manifests.
3. Install the package on the reference phone or another stated target.
4. Record the exact evidence in `COMPATIBILITY_MATRIX.md`. Keep a feature as
   partial or untested when only selection or startup was observed.
5. Package the verified `LSADeploy` directory as a ZIP and publish its SHA-256
   together with the compatibility matrix revision.
6. Tag the source revision used for the package.

The word "stable" applies to the recorded device, Android version, and tested
interfaces. It is not a claim that every Android device has the same kernel,
vendor drivers, permissions, or namespace support.
